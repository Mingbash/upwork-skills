# Upwork Proposal

Environment: Supplied text is sufficient. Optional Python 3.9+ helper validates milestone text; no connector required.

Read the [session/workspace contract](references/workspace.md) and [optional settings](references/options.md). Inputs are job text, relevant user-supplied evidence and material price/time constraints. A cached Profile or screening result is optional. No live balance gate is needed to draft.

## Evidence and fit

Identify the purchased workflow, outcome, systems, stated acceptance and dependencies. Identify the buyer's decision and stated alternatives; leave unknown alternatives unknown. Load a supplied workspace Profile once, or use explicitly supplied experience/files. Do not search for resumes or force profile creation/import. With limited evidence, omit proof claims and ask only decision-changing questions.

Keep a compact internal claim-to-source ledger for personal role, experience, tool familiarity, results and availability. Identify which buyer concern each proof addresses. User self-report is not independently verified; conflicts and unsupported claims cannot become established facts in client copy.

## Draft

Open with the purchase decision or concrete problem and use the most relevant proof to reduce a concern. Use buyer names only when reliably identified. Explain a bounded approach, deliverable, acceptance discussion and useful next step. Answer actual screening questions separately. Match job length/tone rather than enforcing a formula.

Client-facing language follows an explicit requirement, then the job language, then English. Internal analysis follows the user's language. Website links, videos and fixed lines are optional unless explicitly required through settings; include only relevant and accurate material. Flag missing required assets internally rather than inventing a link. A video outline is delivered only when requested/configured, with no vendor requirement.

Follow [proposal decisions](references/proposal-decisions.md) for price, scope and milestone choices. Do not invent experience, guarantee business results, exchange discounts for reviews, or promise unsupported availability. Existing samples do not imply free custom work.

When milestones are warranted, show the same plan in proposal and pricing notes: title, amount/currency, concise client-language description and timing. With a known start date and dependencies, dates are conditional estimates; otherwise use relative durations after access or approval. No default character cap. If a user or verified destination sets one, validate using [milestone helper](references/proposal-decisions.md#milestone-helper) and preserve acceptance details outside the short field.

## Deliver

Return copy-ready proposal, screening answers if present, pricing/milestones with assumptions, and separate internal evidence/unresolved items. Add a video outline only when requested. Save in a new run only if persistence was requested. Follow-up drafts answer the buyer's new decision first; views are views, not proven objections or interest. Do not submit, send, mark submitted or update Profile/preferences.
